# Task 1 — Потерянные инкременты

Файлы: `src/Counter.java`, `LostIncrementsDemo.java`, тест
`test/LostIncrementsTest.java`.

## Инвариант и монитор

Защищаемый инвариант: поле `Counter.value` неотрицательно и равно числу
успешно выполненных инкрементов. Объект-монитор — сам экземпляр `Counter`
(`this`), потому что все изменяющие и читающие методы синхронизируются по нему.

## Почему теряются инкременты

`counter++` — это не одна атомарная операция, а три шага:

1. чтение текущего значения;
2. вычисление `read + 1`;
3. запись результата обратно.

Если две нити прочитали одно и то же значение до записи, обе запишут одно и
то же `read + 1`, и один инкремент потеряется. Демо и тест запускают
8 потоков по 50 000 инкрементов и многократно воспроизводят расхождение
фактического значения с ожидаемым.

## Синхронизированный метод и минимальный блок

`syncIncrement()` — синхронизированный метод: монитор `this`, блокируется весь
метод. `blockIncrement()` использует `synchronized (this)` только вокруг
`value++`. Оба варианта корректны, потому что защищают один и тот же инвариант
одним и тем же монитором. Блок предпочтительнее, когда до или после
критической секции есть полезная работа, которую не нужно удерживать под
блокировкой: меньше время удержания монитора и меньше конкуренции.

Запуск:

```bash
mvn -q -Dtest=LostIncrementsTest test
java -cp target/classes task1.LostIncrementsDemo
```
