# Task 2 — Флаг остановки и visibility

Файлы: `StopFlagWorker.java`, `Task2Demo.java`, `VolatileVsAtomicDemo.java`.

## Некорректный вариант

`BrokenWorker.stop` — обычное поле `boolean`. Поток-исполнитель читает его в
цикле `while (!stop)`. Без `volatile` (или другой синхронизации) JIT вправе
поднять чтение поля из цикла и кэшировать значение в регистре. Тогда запись
`stop = true` из другого потока может остаться невидимой, и worker продолжит
крутиться. Это классическая проблема видимости, а не атомарности.

## Исправление через `volatile`

`VolatileWorker.stop` объявлен `volatile`. Запись в `volatile`-поле
устанавливает отношение happens-before с последующим чтением этого поля:
читающий поток обязан увидеть последнее записанное значение, а компилятор и
процессор не могут вынести или закэшировать чтение так, чтобы запись
потерялась. Альтернатива — читать и писать флаг под общим монитором
(`synchronized`) или использовать `AtomicBoolean`.

## Почему `volatile` не делает `++` атомарным

`volatile` гарантирует видимость и упорядоченность отдельных чтений и записей,
но не атомарность составной операции. `volatileCounter++` по-прежнему состоит
из чтения, вычисления и записи; между чтением и записью другая нить может
изменить значение. Поэтому `VolatileVsAtomicDemo` показывает потерю
инкрементов. Для атомарного счётчика нужен `AtomicInteger` (CAS) или
синхронизация.

`Task2Demo` запускает оба worker-варианта с ограниченным ожиданием и
сравнивает `volatile++` с `AtomicInteger`. `BrokenWorker` может случайно
увидеть `stop` на конкретной JVM, но гарантии видимости без `volatile` нет.

Запуск:

```bash
java -cp target/classes task2.Task2Demo
java -cp target/classes task2.VolatileVsAtomicDemo
```
